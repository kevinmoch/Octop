## 代码归属

- Octop 产品菜单、Dashboard、会话、权限和 HTTP/WS 接线属于 `Octop` 仓库。
- target/frame、浏览器写入协调和 ReplayRunner 执行器属于 `octop-browser`；需要时先走上游独立变更。
- Octop 专属 WebSkill 宿主代码位于 Octop 的 `dashboard/webskill/`；WebSkill 仓库的 `examples/octop-adapter/` 只保留确有必要的参考适配，不放当前产品实现。通用 SDK 缺陷必须在所属包另行评审，不在本专项中假定发版。
- 本目录管理集成需求、设计、探针规范和证据索引，不创建 WebSkill 版本号、npm 包版本或 git 发布 tag；实际探针脚本位于 Octop 仓库的 `scripts/webskill-p0/`。

## 批准范围

- **P0**：基线与真实技术探针，可执行。
- **P1**：主文档 UI、模型、权限和单击闭环，可按 P0 结果实施。
- **P2**：frame、双指针、新 target 工作集、写入锁/lease，可实施并验收。
- **P3**：技能候选、人工录制、录制回放和技能执行，须在 P2 验收后实施；不得绕过本目录定义的 P3 数据与凭证规则。

## 硬约束

1. 不恢复旧控制器网关、专用 iframe 扩展或目标网站 iframe 代理。
2. 不向 WebSkill 前端开放任意 CDP、任意 JS、任意 profile 或任意文件路径。
3. 不把截图当结构化 DOM，不用坐标或同名元素掩盖过期 ref。
4. 不把 Octop 与 WebSkill 的技能、模型、Token、连接器或账本混用。
5. 不把设计闭环、mock、单元测试或构建成功当成真实生产验收。
6. 不将未列入兼容矩阵的组合标为支持；多副本 + `emptyDir` 仅为已有真实证据的 `candidate`，不承诺跨 Pod 共享写入或登录态恢复。

## 当前非承诺

- 不提供动态网页的绝对确定性回放。
- 不保证验证码、反自动化或浏览器私有特权场景的自动化。
- 不把本地源码快照当成 octop-browser 的正式发布证明。
- 不把 P0 探针中的 `candidate` 组合标记为 `supported`。
